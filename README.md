# Security Field Notes

A structured cybersecurity intelligence and research journal.

The goal is to turn daily security news into technical understanding,
defensive recommendations, and practical security research skills.

## Research Workflow

1. Collect news, original reporting, images, videos, and official advisories.
2. Verify claims using primary sources wherever possible.
3. Separate confirmed facts, hypotheses, and unknowns.
4. Analyze the affected architecture, trust boundaries, and attack paths.
5. Evaluate root cause, impact, and confidence.
6. Derive prevention, detection, containment, and recovery measures.
7. Connect the findings to web security and bug bounty methodology.
8. Practice active recall and technical English.
9. Commit the day's work to Git.

## Repository Structure

- `daily-briefings/`: Daily news and learning summaries.
- `incidents/`: Detailed incident case studies.
- `technical-analysis/`: Reusable technical concepts.
- `prevention-and-detection/`: Defensive controls and monitoring.
- `ethical-hacker-stories/`: Documented security researchers and discoveries.
- `active-recall/`: Questions and learning checks.
- `sources/`: Research references and source indexes.
- `progress/`: Learning tracker.

## Evidence Standards

- Confirmed: Supported by reliable evidence.
- Inferred: A plausible explanation that has not been established as fact.
- Unknown: Insufficient evidence to reach a conclusion.

A news report is not automatically proof of a technical attack path.
Diagrams must distinguish confirmed steps from hypotheses.

## Media Policy

Link to original articles and videos whenever possible.
Respect copyright and licenses. Store media files only when reuse is permitted.
Label illustrative images separately from actual incident evidence.

## Security Ethics

All active testing must be authorized and remain within the applicable scope.
